# RAG Evaluation

This folder contains the RAG retrieval evaluation suite.

## Files

- `rag_eval_cases.json`: 50 JSON-defined retrieval cases.
- `rag_eval_runner.py`: batch runner that calls `/api/rag/eval`.
- `results/`: timestamped JSON reports generated by the runner.

## Ports

- `http://localhost:8080`: frontend page served by nginx.
- `http://localhost:8000`: FastAPI backend, exposed by `docker-compose.yml`.

Run eval against `8000`, not `8080`. The runner disables environment proxy
settings with `trust_env=False`, so local requests are not accidentally routed
through a system HTTP proxy.

## Run

Start or refresh the API service first:

```bash
docker compose up -d api
```

From the host:

```bash
python evaluation/rag_eval_runner.py
```

Equivalent explicit form:

```bash
python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

Run a quick subset:

```bash
python evaluation/rag_eval_runner.py --limit 5 --fail-under 0
```

By default, eval uses lexical BM25 retrieval. This keeps the smoke test fast and
avoids cold-start downloads/loads of `BAAI/bge-m3`.

To measure the full vector retrieval path, use hybrid mode and give the first
run enough time to load the embedding model:

```bash
python evaluation/rag_eval_runner.py --retrieval-mode hybrid --timeout 180 --fail-under 0
```

By default, eval also does not run the CrossEncoder reranker. This keeps the
50-case suite usable on a local CPU machine and avoids cold-start downloads of
`BAAI/bge-reranker-v2-m3`. To include reranking in the measurement:

```bash
python evaluation/rag_eval_runner.py --retrieval-mode hybrid --limit 5 --use-reranker --timeout 180
```

Run from inside the API container:

```bash
docker compose exec -T api python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

## Authentication

Defaults come from environment variables when present:

- `EVAL_USERNAME`
- `EVAL_PASSWORD`
- `BOOTSTRAP_ADMIN_USERNAME`
- `BOOTSTRAP_ADMIN_PASSWORD`

If none are set, the runner uses the local development defaults:

- username: `admin`
- password: `CHANGE_ME_TO_A_STRONG_PASSWORD`

Override them when needed:

```bash
python evaluation/rag_eval_runner.py --username admin --password YOUR_PASSWORD
```

## Result

The runner writes a timestamped JSON report under `evaluation/results/`.
It also writes two human-readable summary files beside the JSON report:

- `.csv`: spreadsheet-friendly table for Excel/WPS.
- `.md`: Markdown table for quick review in the editor.

Each case records:

- pass/fail
- failure reasons
- hit count
- elapsed time
- top retrieved chunks with filename, score, chunk id, and preview

The process exits with code `1` when the pass rate is below `--fail-under`.

## Troubleshooting

`502 Bad Gateway` during login usually means the command is hitting the frontend
proxy on `8080`, or the API was still starting. Use:

```bash
python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

Check API reachability:

```bash
curl http://localhost:8000/docs
```

If a case fails with `ReadTimeout`, the runner is working but `/api/rag/eval`
did not return within `--timeout`. For quick local checks, keep the default
lexical mode. If you explicitly enabled hybrid retrieval or reranking, increase
the timeout for a cold model:

```bash
python evaluation/rag_eval_runner.py --limit 1 --retrieval-mode hybrid --timeout 180 --fail-under 0
```

If the report shows `hit_count: 0`, the eval completed but retrieval found no
matching chunks for that case. Check document ingestion status and Agent/RAG
knowledge-base configuration.
