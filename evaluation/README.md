# RAG Evaluation

This folder contains the RAG retrieval evaluation suite.

## Files

- `rag_eval_cases_v3.json`: 160 cases sampled from the uploaded documents (default).
- `rag_eval_cases.json`: legacy 50 hand-written cases, kept only for reference.
- `rag_eval_runner.py`: online assertion runner that calls `/api/rag/eval`.
- `rag_metrics.py`: offline metric harness (hit@k / recall@k / MRR / empty).
- `rag_cases_sampler.py`: generates cases from corpus documents.
- `RAG评测说明.md`: label semantics, chunk unit change, measured baselines, how to run.
- `results/`: timestamped JSON/CSV/MD reports generated by the runner (bind-mounted
  into the `api` and `rag-eval` containers so container runs land here).

For what the numbers mean and which measurement is still missing, read
`RAG评测说明.md` before changing chunking or retrieval depth.

## Ports

- `http://localhost:8080`: frontend page served by nginx.
- `http://localhost:8000`: FastAPI backend, exposed by `docker-compose.yml`.

Run eval against `8000`, not `8080`. The runner disables environment proxy
settings with `trust_env=False`, so local requests are not accidentally routed
through a system HTTP proxy.

## Run

Start or refresh the API service first:

```bash
docker compose up -d api
```

From the host:

```bash
python evaluation/rag_eval_runner.py
```

Equivalent explicit form:

```bash
python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

Run a quick subset:

```bash
python evaluation/rag_eval_runner.py --limit 5 --fail-under 0
```

By default, eval uses lexical BM25 retrieval. This keeps the smoke test fast and
avoids cold-start downloads/loads of `BAAI/bge-m3`.

To measure the full vector retrieval path, use hybrid mode and give the first
run enough time to load the embedding model:

```bash
python evaluation/rag_eval_runner.py --retrieval-mode hybrid --timeout 180 --fail-under 0
```

By default, eval also does not run the CrossEncoder reranker. This keeps the
50-case suite usable on a local CPU machine and avoids cold-start downloads of
`BAAI/bge-reranker-v2-m3`. To include reranking in the measurement:

```bash
python evaluation/rag_eval_runner.py --retrieval-mode hybrid --limit 5 --use-reranker --timeout 180
```

Run from inside the API container:

```bash
docker compose exec -T api python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

## Authentication

Defaults come from environment variables when present:

- `EVAL_USERNAME`
- `EVAL_PASSWORD`
- `BOOTSTRAP_ADMIN_USERNAME`
- `BOOTSTRAP_ADMIN_PASSWORD`

If none are set, the runner uses the local development defaults:

- username: `admin`
- password: `CHANGE_ME_TO_A_STRONG_PASSWORD`

Override them when needed:

```bash
python evaluation/rag_eval_runner.py --username admin --password YOUR_PASSWORD
```

## Result

The runner writes a timestamped JSON report under `evaluation/results/`.
It also writes two human-readable summary files beside the JSON report:

- `.csv`: spreadsheet-friendly table for Excel/WPS.
- `.md`: Markdown table for quick review in the editor.

The eval dashboard's single-case retest action also writes a JSON report under
`evaluation/results/` with a `retest_` prefix. These reports use the same
`summary` and `results` shape as the full runner, but contain exactly one case.
They are meant for preserving investigation history after clicking "复测" in the UI.

The dashboard can also batch retest the currently filtered rows. Batch retest
reports use the `retest_batch_` prefix and contain every case visible under the
current filter, for example all failures matching one failure reason.

The dashboard report API also returns a `trend` array for the most recent
reports. The frontend uses it to show pass-rate, Hit@1 and MRR trends across
runs, not just the delta against the immediately previous report.

Each case records:

- pass/fail
- failure reasons
- `anchor_rank`: the position of the first retrieved chunk containing the case's
  anchor line (`anchor_text`), or empty when it is not in the returned list
- hit count
- elapsed time
- top retrieved chunks with filename, score, chunk id, and preview

The report header carries `summary.rank_metrics`, computed from those per-case ranks:
`hit@1`, `hit@3`, `hit@5`, `mrr`, a rank histogram and the miss case ids.
`pass_rate` alone is not a retrieval-quality number — it only checks that the anchor
appears somewhere in the returned page, which is `hit@<returned chunks>`. The first-place
precision that chunking and fusion tuning aim for is only visible in `rank_metrics`.

Validate the case file and dashboard-readable reports:

```bash
python scripts/check_eval_reports.py
```

The check requires each standard report to include summary metrics, per-case
failure reasons, elapsed time, hit count, and top retrieved chunks with filename,
score, chunk id and preview.

Observed ceiling: `/api/rag/eval` truncates to 5 chunks (`app/rag_eval_api.py:185`) and
the agent worker feeds the model only the first 3 (`agent/worker.py:1014`), so online
`hit@k` cannot be measured past those depths, and online numbers are not directly
comparable with the offline harness, which ranks 30 candidates.
See `RAG评测说明.md` section 5.6.

The process exits with code `1` when the pass rate is below `--fail-under`.

## Troubleshooting

`502 Bad Gateway` during login usually means the command is hitting the frontend
proxy on `8080`, or the API was still starting. Use:

```bash
python evaluation/rag_eval_runner.py --base-url http://localhost:8000
```

Check API reachability:

```bash
curl http://localhost:8000/docs
```

If a case fails with `ReadTimeout`, the runner is working but `/api/rag/eval`
did not return within `--timeout`. For quick local checks, keep the default
lexical mode. If you explicitly enabled hybrid retrieval or reranking, increase
the timeout for a cold model:

```bash
python evaluation/rag_eval_runner.py --limit 1 --retrieval-mode hybrid --timeout 180 --fail-under 0
```

If the report shows `hit_count: 0`, the eval completed but retrieval found no
matching chunks for that case. Check document ingestion status and Agent/RAG
knowledge-base configuration.
